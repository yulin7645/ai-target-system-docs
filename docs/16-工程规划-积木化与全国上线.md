# 工程规划：考情积木化、全国上线、接入学生目标

> 2026-11-14。用户已确认按本文顺序推进，并定为「以工程资产为核心推进」：每次发布对应一个资产版本，资产清单见 `assets/README.md`。考情这一块的探索（成都中考数学）已经做完，数据结构和样式用户认可。本文回答三件事：怎么推到全国、怎么接上学生自己的目标、怎么做成学生能自己搭的积木。

## 0. 结论

1. **对，下一步是「封装成标准做法」。** 探索阶段的成果要沉淀成三样东西：固定的数据格式、确定的生成规则、自动的检查。做到这三样，后面的批量生成大部分**是普通代码，不需要模型**；只有少数「判断」类工作（教材章节对应、官方文件要点、考点标签复核）才用便宜模型（Jev、dsh），而且结果要过检查。
2. **还不能直接推到全部地区。** 现在的统计脚本里有成都数学的写死部分：考点字典只认初中数学，领域分类只写了数学，教材对应只有人教版数学，大题标题按成都卷的格式切。先把这些「去成都化」，再批量生成。
3. **建议的顺序**：先补齐通用的输入（字典、教材、领域）→ 批量生成全国考情数据并自动检查 → 页面改成读数据的通用产品并上线 → 接学生目标 → 积木化开放。官方文件采集可以和前两步并行。
4. **积木的边界从现在就按「数据合同」来定**：每块积木只读上游的标准数据、只写自己的标准数据。考情是第一块积木，目标设定（M1）是第二块，学情画像、备考策略在后面。

## 2. 标准化：考情这块积木的「数据合同」

封装的核心是把每一层的输入输出定死。下游只认格式，不关心上游怎么算的，所以上游可以换便宜的实现。

```
知识点层（全国通用）      题目层（随卷子走）          地区考情层（派生）           展示层
考点字典                  bank/papers                 bank/region-stats/*.json    通用页面
 + 册别、章节             bank/annotations            （表一考点、表二题号、模块） 按地区 × 科目读数据
 + 领域                   题组、题图                  bank/guides/official/*      
 + 教材版本对应           paper-meta（试卷字段）       （官方文件原文和要点）
```

| 层 | 文件 | 谁来生成 | 要不要模型 |
|---|---|---|---|
| 知识点层 | 考点字典、`kp-textbook.json`、领域表 | 一次性建好，人工复核 | 教材章节对应用 Jev 先判，人工抽查 |
| 题目层 | 已有，入库流水线 | 已有 | 已有（读卷、打标签） |
| 地区考情层 | `region-stats/`，规则在 `rules.json` | `region_stats.py` | **不要**，纯代码 |
| 官方文件 | `official/` | 抓取 + 识别 + 提要点 | 要点提炼用便宜模型，原文原样存 |
| 展示层 | 通用页面 | 普通前端代码 | 不要 |

**要写成文档并加检查的三样：**

1. **数据格式（schema）**：每张表的字段、类型、取值，写成可校验的格式，生成后自动校验。现在只在 docs/13 第 9 节写了说明。
2. **生成规则**：已在 `rules.json`，所有地区共用。以后加地区不改代码，改规则要记版本号（现在是 r1）。
3. **自动检查**：每份生成结果过一遍，分「直接报错」和「提醒人看」两类。比如：分值合计对不上满分、某年缺卷、题号对照年份少于 3 年、考点标签可疑比例超过 5%、某个考点从来没考过却被标「升温」。检查结果汇总成一张表，人只看提醒项。

做到这三样，判断「能不能交给便宜模型或纯代码」就有了标准：**只要输出能被检查拦住，就可以交出去。**

## 3. 分阶段计划

### 阶段 1：补齐通用输入（去成都化）

| 任务 | 说明 | 方式 |
|---|---|---|
| 统计脚本读通用字典 | 初中、高中各科都能跑 | 代码 |
| 领域表 | 每科把模块归到课标领域（数学：数与代数等；物理：力、热、电…） | 照课标写，代码 |
| 教材版本对应 | 各科主流版本的目录，每个考点对应到册别和章节 | Jev 判断 + 人工抽查 |
| 地区 → 教材版本 | 每个城市每科用哪个版本 | 先按省级常识定，可修订；没有可靠来源的标「待核」 |
| 卷面大题切分通用化 | 用读卷时记下的大题标题，兼容「A 卷 B 卷」「第Ⅰ卷」等 | 代码 |

**完成标准**：随便挑 20 个不同地区、不同科目，都能生成统计表，并通过自动检查。

### 阶段 2：批量生成全国考情数据

- 一条命令生成全部「地区 × 科目」的统计表。按卷子去重，共用省卷的城市只算一次，再映射到各城市。
- 生成后跑检查，出一张总表：哪些通过、哪些有提醒、哪些数据不够（比如不足 3 年）。
- **数据不够的也上线**，但页面要写明「只有 2 年真题，结论仅供参考」，和之前「残缺卷也收」的规则一致。
- 新卷入库后自动重算对应地区（接到 `bank:ingest` 后面）。

### 阶段 3：官方文件采集（可与阶段 1、2 并行）

- 建一张「地区 → 官方来源」登记表：考试院、教育局网址，栏目地址。
- 抓取最近几年的考试安排通知、考试说明、命题解读、试题发布页，原网页、图片、识别文字都存档（成都已经这样存了）。
- 要点提炼交给便宜模型，原文原样附上，以原链接为准。
- 很多地区找不到或网站打不开，这一块会是长期补的，页面上没有就不显示。

### 阶段 4：考情页面产品化并上线

- 现在的成都页面是一个单文件，把数据和 7 MB 图片都内嵌了，不适合推广。改成线上产品的一个页面：选地区、选科目，读该地区的统计表；原题图走现有题图服务，按需加载。
- 放进现有的 example.com（题库已经在线上），**上线前需要你确认**。
- 页面本身是普通前端，不用模型。

### 阶段 5：接入学生目标（M1）

考情是「这个城市的卷子怎么考」，目标是「这个学生要拿多少分」。两者接起来就是第一层个性化：

| 学生数据 | 来自 | 在考情页上怎么用 |
|---|---|---|
| 地区、科目 | M1 档案 | 自动打开对应的考情 |
| 年级、教材版本 | M1 档案（要新增教材版本） | 标出「已学 / 没学」的考点，按学生的教材显示册别 |
| 保底 B、目标 A、冲刺 S | M1 | 按卷面算「要拿到 A，哪些题位必须拿下」，例如目标 120 分时，把必拿的题位亮出来 |
| 试卷细化（M1 已能上传卷子） | M1 | 以后叠加学生错题，进入学情画像 |

**前提**：M1 现在的档案只存在浏览器里（docs/15 的头号问题）。接入前要先有学生标识和云端档案，否则数据没法跨模块共用。这件事在目标设定分支推进，这边只定接口：考情读学生的哪些字段。

### 阶段 6：积木化开放

- 每块积木 = 输入合同 + 输出合同 + 一个可替换的实现。例如「考情」积木输入是地区、科目，输出是统计表；「目标」积木输入是成绩、志愿，输出是三档目标。
- 学生搭系统，就是选积木、接线。比如「我的地区考情」+「我的目标」→「我的必拿题位」。
- 先在内部用合同把现有模块串起来，确认合同稳定后，再给学生开放搭建界面。界面可以晚做，合同要早定。

## 4. 模型和成本的分工

| 工作 | 谁做 | 原因 |
|---|---|---|
| 统计、趋势、题号稳定性、筛选 | 纯代码 | 规则确定，结果可复现 |
| 页面展示 | 纯代码 | 同上 |
| 考点到教材章节的对应 | Jev | 分类题，有标准选项；结果人工抽查 |
| 考点标签复核 | Jev | 已在用，可疑的进检查表 |
| 官方文件要点提炼 | dsh 免费模型 | 是概括，原文同时附上，错了能对照 |
| 图片文字识别 | 本机识别 | 免费，已在用 |
| 规则和格式的设计、检查规则 | 人 + 强模型（像现在这样） | 一次性的决策，值得花成本 |

**原则**：强模型只用来定标准、处理新情况；标准定下来以后，重复工作交给代码或便宜模型，靠自动检查保证质量。

## 5. 风险和要先定的事

| 事项 | 说明 | 建议 |
|---|---|---|
| 教材版本 | 同一个考点在不同版本里册别不同，地区用哪个版本没有统一官方清单 | 先按省份常识定一个默认值，标「待核」，学生可以自己改 |
| 数据少的地区 | 约 40% 的「地区 × 科目」不足 5 年 | 照样上线，写明年数，不硬下结论 |
| 难度是 AI 判断 | 没有真实得分率校准 | 页面继续写明；以后接学生作答再校准 |
| 原题图版权 | 线上展示原题图 | 现在题库线上已经在展示；对外开放前要再确认使用范围 |
| 页面体积 | 单页 7 MB 不能推广 | 阶段 4 改成按需加载 |
