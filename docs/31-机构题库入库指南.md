# 机构题库入库指南（2026-11-16）

> 给拿到整套系统的合作机构：怎么把你们自己的卷放进来，和我们的题库一起用，又不会在升级时被覆盖。
> 一句话：**按我们的试卷格式写成 JSON → 跑检查 → 放进你们自己的目录。** 原卷是 Word 或 PDF 的，可以先用我们的整理程序转成这个格式。

## 1. 放在哪

```
bank/papers/          我们的卷（每次升级资料包会整体替换，不要往这里放）
bank/org-papers/      你们的卷（升级不碰）
public/bank/img/<卷编号>/   题图，你们的卷也放这里，按卷编号分文件夹
```

**编号加前缀。** 你们的卷编号一律以机构前缀开头，例如 `org1-zk-2025-chengdu-math-mock3`，和我们的编号永远不会撞。前缀由站长分配。

## 2. 试卷格式

一套卷一个文件，文件名就是编号：`bank/org-papers/<编号>.json`。

```json
{
  "id": "org1-zk-2025-chengdu-math-mock3",
  "exam": "中考",
  "subject": "math",
  "year": 2025,
  "regions": ["成都"],
  "title": "2025 年成都中考数学模拟卷（三）",
  "kind": "模拟",
  "full": 150,
  "items": [
    {
      "no": "1", "type": "选择", "points": 4,
      "module": "数与式", "kps": ["实数的概念与分类"],
      "difficulty": "易", "grade": "初一",
      "stem": "题干，公式用 LaTeX 写在 $…$ 里",
      "imgs": ["1.jpg"],
      "parts": []
    }
  ]
}
```

| 字段 | 必填 | 写什么 |
|---|---|---|
| id | 是 | 编号：小写字母、数字、`-`，以机构前缀开头 |
| exam | 是 | `中考` 或 `高考` |
| subject | 是 | `chinese` `math` `english` `physics` `chemistry` `biology` `history` `geography` `politics` |
| year、regions、title | 是 | 年份；地区名列表（中考写城市，高考写省）；卷名 |
| kind | 是 | `真题`、`模拟`、`练习`。**只有真题算进考情统计**（见第 5 节） |
| full | 是 | 满分 |
| items[].no | 是 | 题号，数字，从 1 连续编 |
| items[].type | 是 | `选择`、`填空`、`解答` |
| items[].points | 是 | 分值，大于 0；各题合计应等于满分 |
| items[].module | 是 | 模块，必须是考点字典里这一科的模块之一 |
| items[].kps | 是 | 考点名列表，**必须一字不差地用考点字典里的名字**（`assets/kp-dict.json`） |
| items[].difficulty | 建议 | `易`、`中`、`难` |
| items[].grade | 建议 | 这个考点在哪个年级学（初一…高三） |
| items[].stem | 建议 | 题干；没有的话页面上只显示考点 |
| items[].imgs | 有图才写 | 题图文件名，图放在 `public/bank/img/<编号>/` |
| items[].parts | 有小问才写 | `[{ "sub": "(1)", "points": 3, "kps": [...] }]`，小问分值合计等于本题分值 |

**为什么考点名必须用字典里的：** 考情统计是按考点名汇总的。写成「实数概念」而字典里是「实数的概念与分类」，这道题就统计不到。不知道该归哪个考点的，选最接近的那个，不要自己造新名字；字典确实缺的，告诉我们，下一版字典里加。

## 3. 检查

```bash
python3 -I scripts/bank/check_paper.py bank/org-papers --img-dir public/bank/img --prefix org1-
```

- **错误**（必须改）：缺字段、题型或模块不对、考点不在字典、题号缺了或重复、分值合计差太多、题图找不到。
- **提醒**（可以入库）：没填难度、没有题干、分值合计略有出入、非真题不进统计。

检查只读不改，不联网，只用 Python 标准库。

## 4. 原卷是 Word 或 PDF：用整理程序

整理程序就是我们自己入库用的那一套，在 `scripts/bank/` 里：

1. **登记。** 在 `bank/papers.json`（卷子登记表）里加一行：`{"id": "<编号>", "exam": "中考", "regions": ["成都"], "year": 2025, "subject": "math", "title": "<卷名>", "full": 150, "url": "<原卷文件路径>"}`。
2. **拆题。**
   - Word 卷：`python3 -I scripts/bank/gk/word.py <原卷.docx> bank/raw/<编号>/word.json --subject=math`。不用模型，直接从 Word 里读出题号、分值、题干，公式（MathType）转成 LaTeX，图记成 `[图]`。
   - PDF、扫描卷：要看图识别，跳过这一步，第 3 步不加 `--word`。
3. **标考点、难度。** `npm run bank:read -- <编号> --word`（Word）或 `npm run bank:read -- <编号>`（PDF）。模型拿着考点字典判断每道题的模块、考点、难度，名字自动对上字典。结果写到 `bank/papers/<编号>.json`。
4. **挪到你们的目录、补字段。** 把结果移到 `bank/org-papers/`，补上 `kind`，再做第 3 节的检查。

**模型接口：** 整理程序走 OpenAI 兼容的对话接口，在 `.env.local` 里配，例如 `BANK_LLM=openrouter:<模型名>` 加 `OPENROUTER_API_KEY=…`，或者 `BANK_LLM=deepseek` 加 `DEEPSEEK_API_KEY=…`。费用由你们自己的账号出。

整理出来的结果**一定要过第 3 节的检查**，并且人工抽看几道：模型偶尔会把考点标错、把分值读错。

> 原卷文件本身（Word、PDF）不要放进代码仓库，放在 `bank/raw/` 或你们自己的存储里；仓库和资料包都只放整理好的 JSON 和题图。

## 5. 进不进考情统计

考情（每个题号考什么、哪些年年考、什么在升温）只用**真题**算。模拟卷、练习卷题目再好，也不代表考试院怎么出题，混进去会让结论失真。

- `kind` 是模拟、练习的：放在 `bank/org-papers/`，不进统计。产品里现在还没有单独的练习题板块，这些卷先存着，以后做练习功能时直接用。
- `kind` 是真题、并且我们的题库里没有这一套的（比如你们有某个城市更早年份的真卷）：检查通过后发给我们，我们核对后收进主题库，下一个资料版本里所有人都能用。你们也可以自己把它复制进 `bank/papers/`，再跑 `npm run bank:meta` 和 `npm run bank:guide` 重新算统计，但下次升级资料包时会被覆盖。

## 6. 升级时

- 我们发新的资料包：替换 `bank/papers/`、`public/bank/` 里我们的部分（资料包说明里会写清楚替换哪些目录）。`bank/org-papers/` 和你们的题图文件夹（以你们的前缀开头）不动。
- 我们改了试卷格式或考点字典：版本说明里会写，并附转换脚本。考点改名的，脚本会把你们卷里的旧名字换成新名字。
- 每次升级后，把你们的卷重新跑一遍第 3 节的检查。
